# 观察驱动课程、快照与异步推理合同

## 范围

本文定义真实 CraftGround 训练的课程抽样、世界快照、batch=8、相对优势和异步推理协议。本机没有部署待训练模型时，`gpt-5.6-terra` 可以生成动作作为策略替身，但产物必须保留 `reference_expert` 或 `policy_sample` 来源，不能称为真实策略 rollout。

## 动作与时延

| 项目 | 执行合同 |
|---|---|
| 最小输出 | 每次模型输出至少 8 个 tick 动作。 |
| 推理触发 | 剩余 4 tick 时必须开始下一轮推理；长度足够的序列在剩余 1/4 时预取。 |
| 时延模拟 | 训练时为推理结果附加有上限的墙钟延迟和输入图像 tick；部署时直接用异步推理的实际完成时间。两者均记录提交、开始、完成、消费 tick。 |
| 图像锚点 | 每个动作计划绑定输入图像的世界 tick。结果返回时从该 tick 开始对齐；已经过去的动作直接丢弃，只消费尚能追上的最新连续 tick。 |
| 空队列 | 队列为空时只执行释放所有控制的安全动作，并立刻请求新计划。不得把空队列伪装为模型动作。 |
| 预取失败 | 保留正在消费的旧计划；若不足 4 tick 仍未得到新计划，切换安全动作并记录空置长度。 |

动作队列需要同时保存 `submitted_at_tick`、`input_image_tick`、`start_tick`、`accepted_ticks`、`expired_ticks`、`replan_tick`。这使训练可重放部署时的延迟，而不是以无延迟同步调用掩盖空置。

## GPU 调度

PRO 6000 的优先队列由在线动作连续性决定。在线推理优先于已选 batch 的下一段动作；相对优势计算、训练 batch、轨迹评估和任务生成只使用剩余 GPU 时间。任何空闲窗口可用于评估器克隆学习或相对优势训练，但它们可被在线推理抢占。

| 工作 | 触发条件 | 抢占级别 | 记录指标 |
|---|---|---|---|
| 在线策略推理 | 剩余 1/4 或 4 tick | 最高 | 输入到结果时延、过期 tick、空队列 tick |
| 下一段候选预取 | 当前段仍可消费 | 高 | 命中率、替换次数 |
| 相对优势 | 同快照 batch 完成 | 中 | 排队时间、评分吞吐 |
| 评估器克隆学习 | 无更高优先级工作 | 低 | 训练步、抢占次数 |
| 任务/轨迹生成 | 快照银行缺覆盖时 | 低 | 覆盖增量、GPU 占用 |

本机 Terra 演练不测量真实模型 GPU 利用率、推理吞吐或显存占用。正式训练必须单独记录这些量。

## 同快照 batch 与相对优势

每个训练单元固定为 8 条：2 条 `reference_expert` 和 6 条 `policy_sample`。两个参考轨迹可由人工、经过验证的策略或本机 Terra 替身提供；后者必须在元数据中明确。所有八条在执行前均恢复同一世界状态和同一玩家状态，保存起始、中间和终态 PNG。

相对优势只在同一任务、同一快照、同一预算下比较。评分可以使用任务完成、存活、资源状态、距离进展、耗时和风险惩罚；优势值为候选分数减去该 batch 均分。参考轨迹用于下界锚定、克隆和排序，不混同为待训练策略样本。

两个 `reference_expert` 同时失败不构成任务不可行证据，尤其对复杂长任务。失败可能来自路线、观察不足、预算、控制精度、策略能力或偶然状态。系统必须进入四态可行性判断。

| 状态 | 含义 | 下一步 |
|---|---|---|
| `FEASIBLE` | 至少有一次真实成功或充分的直接物理证据。 | 可进入同快照比较与课程提升。 |
| `UNKNOWN` | 基准失败或信息不足，未获得不可行证明。 | 扩大观察、换策略分支、延长预算或生成信息收集课。 |
| `PREPARATION_REQUIRED` | 当前缺材料、工具、补给或位置条件，但存在可验证的准备路径。 | 生成准备课程并保留原任务。 |
| `INFEASIBLE` | 已获得明确的硬约束证据。 | 不执行该任务，记录证据并选择其他快照。 |

`INFEASIBLE` 仅允许由以下证据触发：必要材料或工具在当前允许范围内不可获得；物理或维度规则禁止；tick 或墙钟预算低于可证明的最短耗时；部署动作或观测精度低于任务所需且没有替代方案。高难度、历史失败率、当前没看到目标、参考轨迹失败都不能单独触发该状态。

`PROGRESSING` 是执行中的状态，不等同于任务成功或失败。长任务在预算结束时仍可保持该状态：位置正确、方法符合游戏规则、并且在最近窗口中存在目标相关的净进展。系统捕获最近稳定检查点，按扩展策略继续执行。

| 字段 | 要求 |
|---|---|
| `progress_metrics` | 记录目标距离、目标方向误差、有效探索覆盖、关键资源/方块状态、存活和路径可回退性。 |
| `method_validity` | 记录当前方法与任务及版本机制的一致性，例如鱼骨采矿、末影之眼三角定位、水上乘船或陆地跑步。 |
| `direction_confidence` | 用连续观测估计目标方向可信度；寻找要塞时由多点末影之眼定位或等效证据支持。 |
| `checkpoint_policy` | 只在玩家稳定、世界状态可恢复、指标净改善时捕获检查点。 |
| `budget_extension_policy` | 超过初始预算但仍有净进展时扩展有限额度；每次扩展必须记录理由和上限。 |
| `stagnation_window` | 在固定滑动窗口内没有目标相关净进展、方向置信度下降或方法失效时停止扩展并转入 `UNKNOWN` 或失败分析。 |

防止刷进度的规则是：移动距离、挖掘方块数或存活时间本身不能通过判定。指标必须与任务目标相关并在滑动窗口中净改善。例如基岩层横向或鱼骨采钻时，下侧出现基岩可作为正确深度证据，但仍需要矿石方向、资源接近或有效覆盖的改善；寻找要塞或末地门时，估计目标距离下降、方向误差收敛或有效航程覆盖才是进展证据。

## 世界与玩家快照

当前 `memorysnapshot` 由世界层和玩家层组成。世界层使用 `StructureTemplate` 恢复受控区域内的方块、流体和方块实体 NBT；玩家层使用 Minecraft 原生玩家 NBT 恢复位置、速度、视角、逐槽背包、选中槽、生命、饥饿、饱和度和经验，并显式恢复状态效果、关闭 GUI、同步背包和客户端位置。

| 层 | 当前实现 | batch 准入要求 |
|---|---|---|
| 世界层 | 内存区域快照 | 保存目标、可落地区域和相关方块实体；恢复后验证区域。 |
| 玩家层 | 玩家原生 NBT + 显式状态效果恢复 + 网络位置同步 | 保存位置、速度、朝向、游戏模式、生命/饥饿、经验、状态效果、选中槽和逐槽背包；恢复后以观测字段做一致性断言。 |
| GUI 边界 | W 位移探针，必要时 inventory/E 中和 | 探针结束后必须再次恢复世界层和玩家层，探针不能成为候选动作。 |

2026-07-31 的真实 CraftGround 验证连续执行 8 次“破坏玩家状态 -> 恢复同一快照”。八次均精确回到 `(0.5, 80.0, 0.5)`，位置、视角、背包、生命、饥饿、饱和度、经验和状态效果全部通过。审计文件为 `runs/player-snapshot-eight-restore-20260731-retry1/report.json`。

玩家状态层仍有明确边界：普通实体、方块计划刻和流体计划刻尚未纳入快照；涉及生物战斗和自动化装置的课程必须先扩展实体状态合同。客户端 GUI 不进入 NBT，恢复时由客户端 `setScreen(null)` 和服务端 `closeHandledScreen()` 双端关闭，并继续保留移动探针。

每个快照记录 `provenance`、父快照、真实观察或成功末态的可行性证据、版本、失败次数和八个课程维度。只有完成这些记录的快照可以进入训练队列。任务成功率达到 75% 时，选取最佳成功轨迹的稳定末态捕获下一快照；否则保留出生快照和失败证据。困难出生点不等于不合格：远树允许跑向树，落水允许游向岸；只有硬约束证明在预算内无法完成时才标记 `INFEASIBLE`。

## 多起点课程银行

课程不从出生点单线推进。快照银行从不同科技阶段、装备、地形、风险、资源和策略状态分层抽样，先满足覆盖下限，再以失败次数提高重采样权重。每条候选还要带版本和机制依赖，避免版本变动使看似合理的任务失效。

| 能力种子 | 关键真实前置 | 路线或机制校正 |
|---|---|---|
| 铁镐采钻石 | 铁镐、可见钻石、可安全挖掘路线 | 目标矿石和工具均需快照证据。 |
| 钻石镐采黑曜石 | 钻石镐、黑曜石、岩浆控制 | 需要恢复路线和安全区。 |
| 垫脚方块、食物补给 | 方块、食物、返程余量 | 资源管理状态纳入快照。 |
| 村庄利用、铁傀儡和一般战斗 | 目标可见、武器或撤离方案 | 生物 AI 不在当前世界快照范围，须扩大协议。 |
| 下界门、堡垒和烈焰人 | 黑曜石门、下界准备、堡垒或烈焰人证据 | 前往下界依赖黑曜石下界门。 |
| 刷铁机 | 村民、结构材料、目标版本机制验证 | 不把旧版本结构直接迁移。 |
| 船机制末影人、要塞、末影龙 | 船/末影之眼/末地门/战斗装备的对应证据 | 末影之眼仅在主世界寻找要塞和末地门，不用于前往下界。 |

课程维度固定为 `stage`、`inventory_loadout`、`biome_terrain`、`hazard`、`health_hunger`、`route`、`strategy`、`version_mechanic`。`tools/curriculum_bank.py` 保存能力本体、快照验证、覆盖矩阵和分层抽样实现。它只定义待验证课程，不能产生未观察到的资源或装备。

## 任务生成与评估学习

模型需学习三类互补工作：生成合理任务、产生动作轨迹、比较同任务轨迹的相对优势。任务生成先受快照可行性门约束；优势评估只看同快照的相对事实；评估器克隆学习在 GPU 空闲窗口训练，并与在线策略推理抢占隔离。

由模型生成的两条高质量参考轨迹可以进入 2 条 `reference_expert` 位，但必须保存生成者、提示、输入观察、动作和审计结果。剩余 6 条为 `policy_sample`。训练先使用相对优势，不把模型自评的绝对分数当作无条件真值；对分歧大的排序样本保留人工或更强模型复核队列。

## 视觉微调合同

`640x360` 是当前 CraftGround 基准样本，不是输入格式限制。训练、验证和部署可以使用多种实际分辨率和宽高比；每条样本必须保存自己的原生宽高和几何变换。训练可使用尺度扰动提高鲁棒性，但不能以强行拉伸覆盖真实宽高比差异。

| 项目 | 合同 |
|---|---|
| 尺度范围 | 训练短边可在样本原生尺寸的 `0.8x-1.25x` 内扰动；保留样本原始宽高比。课程依赖小 UI、F3 坐标或物品数量时提高最小尺度，确保关键文字仍可读。 |
| Patch / stride | resize 后的宽高按视觉模型 patch 或 stride 向上对齐；对每个实际宽高比选择 letterbox 或保留目标区域的 crop，并记录策略和补齐区域。 |
| 目标几何 | 鼠标视角增量、鼠标点、目标点、框和分割掩码按该样本实际宽高归一化；所有 resize、letterbox 和 crop 后按变换后的实际宽高反归一化。 |
| 裁剪 | 对几何敏感的时序动作不使用破坏性随机裁剪；需要裁剪时保证目标、鼠标锚点和行动路径仍完整可见。 |
| 验证集 | 覆盖当前 `640x360`、其他实际宽高比和训练未见尺度；报告分别给出各尺寸桶指标及整体指标。 |

每条训练样本应记录原生尺寸、变换矩阵、变换后尺寸、patch 对齐、归一化动作坐标和最小可读尺度检查结果。这样数据增强不会把视觉几何错误传递到鼠标控制或任务定位。

### Gemma4 视觉预算

当前已核对的 Gemma4 图像配置为：`patch_size=16`、`pooling_kernel_size=3`、默认 `max_soft_tokens=280`、`max_patches=2520`，可选 soft token 预算为 `70/140/280/560/1120`。图像处理器按其宽高和 patch 预算进行缩放、patch 对齐和必要填充；不要把 `640x360` 误认为唯一输入格式。

当前 `640x360` 样本的处理链为：`640x360 -> 1056x576 -> 66x36=2376` 个原始 patch，经过 `3x3` 池化后得到 `22x12=264` 个 soft tokens；`2376` 小于 `2520` 的原始 patch 上限。其他宽高比必须各自经过同一预算计算并记录结果。

对原始图像宽高 `(W,H)`，图中点使用 `u=(x+0.5)/W`、`v=(y+0.5)/H` 保存。相对鼠标视角输入使用 `du=delta_x/W`、`dv=delta_y/H` 保存；送入某一处理后图像 `(W',H')` 时反归一化为 `delta_x'=round(du*W')`、`delta_y'=round(dv*H')`。目标框、分割掩码和鼠标点都使用同一坐标变换矩阵。letterbox 时先移除 padding 再反归一化；crop 时同步更新可见区域原点。这个规则适用于所有实际输入尺寸和宽高比。
