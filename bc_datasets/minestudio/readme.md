# MineStudio 10xx v1.1.0 数据分析

本文档描述本地快照 `CraftJarvis/minestudio-data-10xx-v110`。分析时间为 2026-07-29。除特别标明为抽样的统计外，文件、LMDB 元数据、动作和事件统计均来自完整数据。

## 结论摘要

| 项目 | 结果 |
| --- | ---: |
| 本地数据总量 | 156.75 GiB |
| 基准轨迹数（`action`） | 1,846 |
| 基准帧数（`action`） | 18,752,288 |
| 视觉时长（20 FPS） | 约 260.45 小时 |
| 录制主体前缀数 | 19 |
| 名义会话 ID 数 | 1,183 |
| 录制日期范围 | 2022-04-13 至 2022-04-24 |
| LMDB 块长度 | 32 帧或记录/块 |
| 六模态都存在的轨迹 | 1,810 |

数据内容以第一人称 Minecraft 生存、采集和制作过程为主。事件与背包分布中，圆石、木材、煤、熔炉、工作台、各级镐和矿石频繁出现；事件侧最常见的具体任务是移动、挖掘石头、拾取圆石和使用镐。

## 统计口径

| 统计项 | 范围 | 口径 |
| --- | --- | --- |
| 文件大小、轨迹、帧数、时长、主体和日期 | 全量 | 读取全部文件属性及各 LMDB 的 `__chunk_infos__` |
| 动作字段与组合 | 全量 18,752,288 帧 | 解码全部 586,009 个动作块 |
| 相机非零率、均值和极值 | 全量 | 解码全部动作帧 |
| 相机分位数 | 1,172,018 帧 | 每个 32 帧块固定取第 0、16 帧，占动作帧 6.25% |
| 事件类型和数量 | 全量 | 读取 `event/__event_info__`，与 LMDB 条目数交叉核对 |
| 状态元数据 | 176,256 帧 | 每条轨迹取首、中、尾各一个 32 帧块，短轨迹重复块去重 |
| 实例分割 | 176,448 帧 | 每条轨迹取首、中、尾各一个 32 帧块，短轨迹重复块去重 |
| motion 语义标注 | 173,824 条记录 | 每条轨迹取首、中、尾各一个 32 记录块，短轨迹重复块去重 |
| 图像编码 | 分片探测 | 从各分片解封装视频块；未进行全量像素语义分类 |

抽样统计是按轨迹和时间位置分层的确定性样本，不是简单随机帧样本。长短轨迹获得相近的块数，因此它表示“典型轨迹”的内容分布，和按总帧加权的结果可能不同。

## 轨迹分布

### 模态覆盖

| 模态 | 轨迹数 | 帧/记录数 | 按 20 FPS 折算 | 相对 `action` 的缺失轨迹 | 同名轨迹长度情况 |
| --- | ---: | ---: | ---: | ---: | --- |
| `action` | 1,846 | 18,752,288 帧 | 260.45 小时 | 0 | 基准 |
| `image` | 1,845 | 18,707,040 帧 | 259.82 小时 | 1 | 1,841 条等长，4 条较短 |
| `meta_info` | 1,843 | 18,729,024 帧 | 260.13 小时 | 3 | 1,843 条均等长 |
| `segmentation` | 1,845 | 18,707,040 帧 | 259.82 小时 | 1 | 与 `image` 的轨迹和长度完全一致 |
| `motion` | 1,818 | 18,247,808 条 | 不直接折算 | 28 | 406 条等长，1,412 条记录数较少 |
| `event` | 1,838 | 59,377,974 条事件 | 不适用 | 8 | 倒排事件记录，不是逐帧流 |

六模态交集为 1,810 条轨迹。训练多模态模型时应先按轨迹名取交集，再按各模态实际长度裁剪。分片编号不能用于跨模态对齐：例如 `action/part-1904`、`image/part-1903` 和 `meta_info/part-1901` 的边界不同。

`image` 和 `segmentation` 缺少同一条轨迹：

```text
cheeky-cornflower-setter-6cdc9b43a3a1-20220414-154844
```

另有 4 条视觉/分割轨迹比动作短，合计少 28,992 帧，单条差值为 2,016 至 12,832 帧。`motion` 中的 `tick` 保存原始时间位置；其 LMDB 记录序号不能直接当作视频帧号。

## 各模态内容

### image

每个 LMDB value 是一个独立 MP4 视频块。探测到的编码规格一致：

| 属性 | 值 |
| --- | --- |
| 分辨率 | 224 × 224 |
| 帧率 | 20 FPS |
| 每块帧数 | 32 |
| 视频编码 | H.264 |
| 像素格式 | YUV420P；项目读取器转换为 RGB24 |

内容是 Minecraft 第一人称游戏画面，包含自然场景、洞穴、采矿、物品栏与工作台/熔炉等 GUI。本文没有对 18,707,040 张图像做全量视觉分类；任务内容比例优先使用动作、事件、状态和分割标注计算。

### action

每个块是 pickle 字典。`camera` 为 `float64[32, 2]`，列序为 `[pitch, yaw]`，单位为度；其余字段为 `int64[32]` 的逐帧二值状态。

#### 字段激活率

激活率是“该字段值非零的帧数 / 全部动作帧”。按键持续按住会连续计数，因此它不等于点击次数。

| `sneak` | 1,234,750 | 6.58% |
| `right` | 1,004,862 | 5.36% |
| `jump` | 972,584 | 5.19% |
| `left` | 656,184 | 3.50% |
| `use` | 453,514 | 2.42% |
| `back` | 349,234 | 1.86% |
| `inventory` | 98,633 | 0.53% |
| `hotbar.2` | 33,045 | 0.18% |
| `hotbar.1` | 29,139 | 0.16% |
| `hotbar.5` | 20,736 | 0.11% |
| `hotbar.3` | 20,417 | 0.11% |
| `hotbar.4` | 19,115 | 0.10% |

### meta_info

每帧包含固定 14 个字段：

```text
yaw, pitch, xpos, ypos, zpos, hotbar, inventory,
isGuiOpen, isGuiInventory, delta_yaw, delta_pitch,
events, cursor_x, cursor_y
```

`inventory` 是 `[{"type": ..., "quantity": ...}, ...]`；`events` 是该帧事件名到增量的字典。

| 状态 | 样本帧数 | 比例 |
| --- | ---: | ---: |

| 任意 GUI 打开 | 14,103 | 8.00% |

选中快捷栏位置以 0 开始。位置 0 占 47.49%，位置 1 占 13.53%，其余单个位置各占 3.51% 至 7.02%。

### event

`event` 是倒排索引，而不是逐帧数组：

```text

```

`__codebook__` 把轨迹名映射到 `episode_code`，`__event_info__` 保存每类事件的轨迹数和记录数。LMDB 含 59,377,974 条事件记录和 3 条元数据记录，共 59,377,977 个条目。

### segmentation

每个块是长度 32 的列表，每帧是对象字典。对象包含：

```text
obj_id, rle_mask, event, point,
ori_frame_id, ori_frame_range, frame_id, frame_range
```

`rle_mask` 是压缩游程字符串。抽样 RLE 最大端点为 230,401，表明掩码坐标基于约 640 × 360 的原始画布，而 `image` 已缩放为 224 × 224。使用前需要按原始尺寸解码并缩放，不能直接与 224 × 224 图像逐像素叠加。

## 读取与训练注意事项

1. 使用轨迹名进行跨模态连接。各模态分片边界和 `episode_idx` 都是局部的。
2. 每个常规模态 LMDB 的 key 是字符串化的 `(episode_idx, chunk_start)`；`chunk_start` 是 0、32、64 等块起始位置。
3. 先读取 `__chunk_size__` 和 `__chunk_infos__`，再构造数据 key。最后一个块应按 `num_frames` 截断。
4. `image`、`action`、`meta_info` 和 `segmentation` 可以按帧对齐，但必须取共同长度；`motion` 应通过记录内的 `tick` 对齐。
5. `event` 的 `episode_code` 必须通过 `__codebook__` 反查轨迹名。
6. 数据在主体、任务和动作上均不均衡。主体级验证集应按轨迹名前缀隔离，避免同一录制主体同时进入训练集和验证集。
7. `attack` 是逐帧按住状态，55.74% 的高占比不能解释为独立攻击次数；独立任务事件应优先从 `event` 读取。
8. 三类持续时间事件占事件表 87.36%。训练事件模型时应单独降采样或排除。
9. 分割掩码和图像分辨率不同，需显式解码、缩放并验证坐标方向。
10. pickle 只应从可信数据源加载。本快照来自指定 Hugging Face 数据集仓库。

项目内可使用 `bc_datasets/minestudio/lmdb_modal_reader.py` 读取 `image`、`action` 和 `meta_info`，并按轨迹名建立多模态交集。
